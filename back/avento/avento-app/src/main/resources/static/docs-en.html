Avento - Technical Documentation

Updated July 25, 2026Local-firstAuth + Projects + Voice + ToolsComfyUI Media

Avento is a local-first AI assistant for software projects and personal workflows. Its main objective is to serve as an active pair programming partner: inspecting user-authorized codebases, providing real-time feedback, safely running local tools, editing files, running validations, and interacting via voice.

The system runs on a Spring Boot Multi-Module Maven backend, React 19 / Vite frontend, local HttpOnly JWT auth, PostgreSQL 16 and Redis Stack via Docker/Colima, host-native Ollama, local RAG, automated backups, WebSocket voice streams, and optional Whisper.cpp/Piper TTS engines.

Origin & Author

Avento is an independent personal project conceived, designed, developed, documented, and maintained by Samuel Tomimatu, software engineer and sole creator of Avento. No other person or organization should be credited as the author of the project.

Its personality is that of a direct, curious, and reliable technical collaborator: concise by default, detailed when requested, natural in the user's language, and careful to distinguish verified facts from inferences. It preserves context references, avoids hyperbolic marketing, and never announces execution without verified results.

Quick Start

Launch the complete stack with a single script:

./scripts/dev-up.sh

This script checks dependencies, reconciles Docker containers without losing volume data, starts PostgreSQL and Redis Stack, verifies Ollama, launches ComfyUI, backend, and frontend, and runs an authenticated smoke test. Terminal displays live logs and ports.

Current Architecture

Frontend

React 19 + Vite in front. Chat, workspace selector, file tree, SSE streaming, and voice controls.

Backend

Spring Boot in back/avento organized into Multi-Module Maven submodules (avento-core, avento-auth, avento-workspace, avento-mcp, avento-execution, avento-agent, avento-media, avento-voice, avento-rag, and avento-app).

Local AI

Host-native Ollama. Agent uses /api/chat for streaming and tool calls.

Local Infra

PostgreSQL 16 and Redis Stack via Docker/Colima. PostgreSQL handles durable state; Redis handles jobs, streams, vector RAG, and SSE event dispatching.

Redis, Jobs & Streaming

Chat requests do not block HTTP connections. Frontend submits jobs via POST /api/ai/runs, receives runId, and listens to GET /api/ai/runs/{runId}/events via authenticated SSE.

  1. Persistence: Jobs and Outbox events are saved together in PostgreSQL.
  2. Publication: Dispatcher publishes jobId and runId to avento:jobs:agent.
  3. Execution: AgentRunWorker consumes jobs with consumer group avento-agent-workers.
  4. Feedback: Text, thinking, and tool events enter Redis Streams and reach UI via SSE.
  5. Acknowledgment: Worker issues XACK after saving final state to PostgreSQL.

Ollama & Mac Acceleration

On macOS, run native Ollama on host for Metal acceleration in Apple Silicon. For agent execution and planning, granite4.1:8b is configured as default (3x faster tool calling and zero VRAM model-swapping latency). Models like qwen3.5:9b, qwen3:8b, and qwen2.5vl:7b are also supported.

ollama pull granite4.1:8b ollama pull qwen3.5:9b ollama pull qwen2.5vl:7b ollama pull llama3.2 ollama pull nomic-embed-text

REST Endpoints Summary

JSON REST endpoints return envelopes with status, code, and data.

EndpointFunction
GET /api/healthBackend health check.
POST /api/auth/loginAuthenticates user and sets HttpOnly access cookie.
POST /api/ai/runsSubmits asynchronous job to PostgreSQL outbox.
GET /api/ai/runs/{runId}/eventsListens to run events via SSE stream.
POST /api/mcp/executeExecutes authorized MCP or local tools.
