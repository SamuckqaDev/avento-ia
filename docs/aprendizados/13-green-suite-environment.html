Learning 13

A green suite proved less than it looked

A delegated agent reported mvn clean test green twice. The result was true, but it did not exercise what its report implied: the sandbox could not reach the real containers.

Symptom: known leaks did not appear

The suite is known to leave scheduled Cowork tasks in Postgres and @TempDir RAG keys in Redis when it runs against the owner's infrastructure. After the delegated run, scheduled_tasks was empty and the RAG-key count was exactly 954. That was not evidence that the suite had become clean.

What was checked after the runObserved
Postgres scheduled_tasksEmpty
Redis RAG keysExactly 954

Cause: the same command had a different environment

The agent sandbox had no path to Postgres or Redis. Tests whose real-infrastructure paths would normally write there degraded instead of writing. Maven still reported a green suite because the tests completed under the conditions available to it.

Owner's machine
Tests reach Postgres and Redis; leak paths can execute.
→
Agent sandbox
Containers are unreachable; those paths degrade.
→
Same Maven command
Both can be green, but they prove different things.
Green is a result, not a coverage map. It says the checks that actually ran passed; it does not prove that unavailable infrastructure paths were exercised.

Fix: report the environment with the result

The operational fix is reporting where a suite ran: local machine with its containers, or sandbox without them. The larger open task is to isolate tests from real infrastructure so neither environment can silently substitute for the other.

A test report without its execution environment is incomplete evidence.

The lesson

The same suite means different things in different environments. A green sandbox run does not prove paths that require real infrastructure. State the environment whenever you report the suite green.
